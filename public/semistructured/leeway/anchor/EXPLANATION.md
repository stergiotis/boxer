# anchor — the leeway / nanopass / keelson showcase table

`anchor` is a demo and fixture package built around one leeway table (the
"anchor" schema, `anchor.facts` in ClickHouse). It exists to show the three
subsystems working together on one concrete example — leeway's columnar
modelling and codegen, nanopass's treatment of SQL as a data structure, and
keelson's data plane — and it doubles as a shared test fixture
(`marshall/go/marshallreflect_test/` binds its round-trip tests to this
schema, so schema changes must stay additive).

Three fictional demo domains (drone missions, alpine sensors, cyber
incidents) share the single schema; the cross-domain queries are the payoff
of that sharing. Everything execution-shaped is generated: the DDL, the DML
builders, the read-access classes and the executable SQL are all `.out.*`
artifacts regenerated by the tests in this package.

## The pipeline in one sentence

Queries are authored once, in friendly form — leeway column handles
(`` `symbol:value` ``, ADR-0116) and unqualified tables — and the nanopass
pre-execute chain (strip comments → canonicalize → qualify → resolve →
grammar2-validate) produces the physical SQL that ships to ClickHouse; the
friendly text is for people, the generated `.out.sql` is for executors, and
nothing in between is written by hand.

## Tour — file → what it shows

### Schema and codegen (leeway)

| Artifact | Shows |
| --- | --- |
| `card_anchor_schema.go` | The fluent `TableManipulator` schema: plain columns, ~25 tagged sections, four membership specs, streaming groups, co-containers, encoding/use/value aspects. |
| `card_anchor_gen_test.go` | The three codegen drivers writing `card_anchor_ddl_clickhouse.out.sql` (DDL), `card_anchor_dml.out.go` (entity builders) and `card_anchor_ra.out.go` (read-access classes). |
| `card_anchor_data_{drone,avalance,cyber}.go` | The generated DML builders driven by hand: BeginEntity/attributes, memberships (`lr`/`hr`), co-containers, `*Single` helpers, sparse sections. |
| `codecdemo/`, `codecdemo/nested/` | The `lw:` tag grammar → `keelsoncodec` marshallgen codecs bound to this schema; gen≡reflect byte-identity witnesses; the ADR-0109 multi-membership tuple shapes; the generated RA classes driven read-side in the round-trip tests. |
| `ecsdemo/` | One ECS model twice: `encoding/json/v2` (stage 1) vs leeway + ClickHouse with the ADR-0066 presence/validator/projection read-back (stage 2); see `ecsdemo/EXPLANATION.md`. |

### The DQL path (nanopass + lwsql)

| Artifact | Shows |
| --- | --- |
| `card_anchor_dql_query{1..7}.sql` | The friendly-handle sources. 1–6 compute (ragged regrouping via the ADR-0162 pack's `raggedNest`, cross-domain H3 correlation, wordBag token search, silver/gold tier reshaping, integrity scanning); 7 is a plain retrieval read. |
| `card_anchor_dql_pipeline.go` | The pre-execute chain and its schema wiring: a `StaticSchemaProvider` fed from the generated Arrow schema, the `lwsql.Resolver`, and the stage list ending in `ValidateGrammar2`. |
| `card_anchor_dql_test.go` | Regenerates the executable `card_anchor_dql_queryN.out.sql`, the stage-by-stage `card_anchor_dql_pipeline.out.md`, and the `card_anchor_dql_analysis.out.md` report (statement kind, security class, tables/columns/functions, ADR-0117 passthrough triage). Asserts zero unresolved handles, grammar2 validity, and idempotence. |
| `card_anchor_dql_lwsql.out.md` | ADR-0121 selection conditions on query 7 in both naming modes (`cond_N` vs a physical `conditions` section), and `BuildLabels` mapping every physical column back to a display label. |
| `card_anchor_dql_typedliteral.out.md` | The marshalling bridge: Go values → SQL literals (escaping, `PreserveCasts`), and `ExtractLiterals` turning query 2's literals into named parameters that round-trip through `TypedLiteral` losslessly. |

Two scope rules the sources honour, on purpose: handles live where their
table is in scope (the resolve pass does not reach through subqueries — see
query 2/5), and a query-level `WITH expr AS name` clause is outside the
pass's walk (query 1 inlines its pack call instead; deferred: teach
ResolveColumnNames the query-level WITH clause).

### The keelson data plane

| Artifact | Shows |
| --- | --- |
| `card_anchor_passreg_test.go` | The ADR-0108 seam: host-order entries plus the standard set (`passreg/defaults`, with the late-bound resolver factory), the ADR-0094 catalog rows, the per-pass observation trace, and byte-equality with the directly-composed chain. |
| `card_anchor_integration_test.go`, `card_anchor_integration2_test.go` | The integration lane (`-tags integration`, live server): `keelson/data/chclient` for ping/DDL/Arrow-IPC-insert/query — the client that was originally modelled on this package's hand-rolled HTTP code — with connection coordinates from the `clickhouseenv` registry; the friendly correlation query rewritten live and shipped with `SetFormat`. |
| `ecsdemo/stage2/roundtrip_test.go` | `keelson/data/chlocalpool` (ADR-0028): the readback scripts run in a pre-spawned single-use `clickhouse-local` worker, binary resolution via the extbin chokepoint (ADR-0118). |

The runtime facts store is the production-scale consumer of the same
leeway machinery shown here — `keelson/runtime/factsschema` describes
`boxer.facts` with the same TableDesc/DDL/DML/RA drivers this package
demonstrates. It is deliberately not imported here; anchor showcases the
data pillar (`keelson/data/*`) and leaves the runtime spine by reference.

### Reading it back (streamreadaccess, card, membership)

| Artifact | Shows |
| --- | --- |
| `card_anchor_integration3_test.go` | The `streamreadaccess.Driver` over generated batches feeding the card emitters: structured recorder, Unicode, JSON and HTML cards, and the schema emitter with its blake3 fingerprint (all golden-pinned). |
| `card_anchor_membership_test.go` | The ADR-0072 representation plane: ids on the wire, names at read time — a demo-local `RefFormatterI` injected via `WithRenderer` swaps hex refs for domain names in the card JSON; and the `membershiprole.DefaultClassifier` policy tabulated against anchor sections. |

## Regenerating

`go test` in this package rewrites every `.out.*` artifact it owns (the gen
tests write unconditionally); the integration lane executes what the unit
lane generated. `seed_facts.sh` populates a live `anchor.facts` for
interactive use. Build with the repo tags, as everywhere:
`go test -tags="$(cat ../../../../tags)" ./...`.
