# How to follow the I/O context change

[ADR-0395](../adr/0395-io-takes-a-context.md) puts `ctx context.Context`
first on every I/O interface and removes the ctx-less twins. No stored table
and no wire format changes. A consuming module regenerates its generated
stores, then passes a ctx at each call the compiler reports. Changes of
behaviour from the same period that compile unchanged are listed in
[2026-11-behaviour-changes.md](./2026-11-behaviour-changes.md), and the app
contract that changed with them in
[2026-11-app-contract.md](./2026-11-app-contract.md).

## When to use this recipe

You import a boxer package, or generate a record store with boxer's
generator, and upgrade past this change. The symptom of skipping it is a
build failure: `not enough arguments in call to …`, an undefined
`BeginCtx`, `RequestWithTimeout` or `RequestCtx`, or a type that no longer
implements one of the interfaces below.

## Which ctx to pass

- Inside a function that has a ctx: that ctx.
- In a bus request handler: `msg.Context()`, the requester's; for a row that
  must land whether or not the requester still waits,
  `context.WithoutCancel(msg.Context())`.
- In an app with no call context (`Frame`, a button's handler): keep
  `app.ContextOf(mountCtx)` from `Mount` in a field and pass it. A test that
  builds the app without mounting it sets the field to `t.Context()`.
- At shutdown: the ctx `hostboot.Runtime.Close` and `OnClose` hand you.

## Writes at stop

A write now runs under the ctx it is given, so a write under a context that
stop has already cancelled does not land, and a store that disables itself
after a failed write then drops every row after it. The last flush and the
close of a recording pipeline — a producer, a sink, a recorder — run under
`context.WithoutCancel(producerCtx)`, bounded by a timeout of their own
(`context.WithTimeout` over it), not under the cancelled producer context.
The same holds for a bus handler's row that must land
(`context.WithoutCancel(msg.Context())`, above).

## Generated stores

1. Regenerate every store generated with `public/storage/recordstore/gen`.
2. Rename: `X.BeginCtx(` → `X.Begin(`, `X.DeleteCtx(` → `X.Delete(`,
   `X.Ingest<Kind>Ctx(` → `X.Ingest<Kind>(`.
3. Every remaining `Begin(id, order[, env])`, `Delete(id, order)` and
   `Ingest<Kind>(order, rows)` takes the caller's ctx first.

Order matters when a store is generated by a test. Its generator test
compiles the package's test binary, so it cannot run while hand-written code
in a package that binary imports still calls the old generated API — and
that code cannot be fixed against an API that is not generated yet. Either
regenerate the store first, fix its callers, then regenerate the stores
that depend on it; or first make the callers compile against the old API
(pass the ctx through the `…Ctx` forms), regenerate, and rename.
