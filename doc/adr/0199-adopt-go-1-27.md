# ADR-0199: Adopt Go 1.27

## Context

[Go 1.27](https://go.dev/doc/go1.27) shipped in August 2026. Four of its changes
land on decisions this repository already recorded.

**A deferral comes due.** `public/gov/buildtags` says of `RequiredTags`:
"Retires when `encoding/json/v2` graduates into the standard library, at which
point this set is expected to become empty and a consumer needs no build tags at
all." It graduated. The same forecast is costed in
[downstream-adoption-skeleton](../adr-background-work/downstream-adoption-skeleton.md)
§The tag endgame, which also predicted that `go tool` delivery would open up for
consumers once the required set is empty.

**A stated rationale becomes void.** [ADR-0023](./0023-leeway-lwq-go-api.md)
says twice that its type-introducing terminals are free functions "because Go
does not allow generic methods", and calls the result "less fluent than
fully-chainable APIs in other languages". 1.27 allows them.

**A profile becomes predefined.** `goroutineleak` graduated from the 1.26
experiment to a `runtime/pprof` profile and a `net/http/pprof` endpoint.

**And a sweep was overdue.** `go fix`'s modernizers are not a 1.27 feature —
`go1.26.5` already registered 23 of them, none applied here.

**Why one ADR and not four.** The parts are not independent. Retiring the tag is
only correct once consumers are on 1.27, and the `go` directive is what forces
that; generic methods need the same directive; the profile needs the same
toolchain. A consuming repository does not experience four changes, it
experiences one bump, and the ordering between them is the decision.

Measurements — the tag matrix, the `go tool` delivery probe, the API diff, the
`goroutineleak` cost, the `go fix` census, the staticcheck and capslock
findings — are in
[Go 1.27 — what it retires, what it unlocks, and what the adoption costs](../adr-background-work/go-1-27-adoption.md).
They are not repeated here.

## Decision

We move the module to Go 1.27, retire the last required build tag, and take the
consequences as one change. Six decisions, each stated once:

| | Decision | State |
| --- | --- | --- |
| **D1** | The module declares `go 1.27.0`. `go mod tidy` drops the now-redundant `toolchain` line; the `go` directive drives selection either way | shipped `42f1dc4b` |
| **D2** | `goexperiment.jsonv2` leaves `RequiredTags` and enters `RetiredTags` with this ADR. `./tags` keeps `boxer_enable_profiling` alone; a consumer needs no tags | proposed |
| **D3** | `go fix` is a **reviewed sweep once per Go release**, not a gate. Its output is reviewed per fixer and may be declined | shipped, M0 |
| **D4** | `goroutineleak` joins the profile roster, and replaces the goroutine-counting slack in the task-spawn leak test | proposed |
| **D5** | The `staticcheck` step is **parked, visibly**: `lint.sh` prints `DID NOT RUN` when the tool aborts, and stays `warn` rather than `fail` | shipped `42f1dc4b` |
| **D6** | Generic methods are adopted only where a fluent surface is currently blocked by their absence — `marshallreflect`'s terminals, and `FatRow.Extract`. ADR-0023's rationale is void and its design is edited in place | proposed |

### SD1 — the tag is *retired*, not merely *not required*

`RetiredTags` means "must not be present at all", and a finding names the ADR
that retired it. That is the right classification even though a stale tag is
harmless under 1.27: measured, a build with the tag, without it, and with no
tags at all give identical results, because 1.27's standard library still
carries the `//go:build goexperiment.jsonv2` constraint and `internal/buildcfg`
now sets the flag true by default. The tag is *recognised*, not unknown — so a
consumer carrying it is carrying a tag that means something, which is exactly
the drift the gate exists to report.

The ordering objection resolves itself: `RetiredTags` reaches a consumer through
the module pin, so a consumer that has not bumped the pin never sees the
finding, and one that has is on 1.27 by D1.

### SD2 — `boxer_enable_profiling` stays

It selects between `profiling_enabled.go` and `profiling_disabled.go`, and the
enabled arm blank-imports `net/http/pprof`, which registers debug handlers on
`http.DefaultServeMux` as an import side effect. Making that unconditional is a
different decision with a security surface. boxer goes two tags to one; a
consumer goes two to zero, because the disabled arm is the default.

### SD3 — a parked check must say so

`lint.sh`'s staticcheck step is warn-only, so a panicking tool produced a stack
trace filed under "warnings" — a check that analysed nothing reading as a check
that ran. The step now detects the abort and says `DID NOT RUN`. It stays `warn`
rather than `fail` because a third-party bug should not block the build, and the
[static-analysis table](../ENGINEERING_PRACTICES.md#2-static-analysis) carries
the same statement so the roster does not claim coverage it lacks. Delete the
branch when a working release ships.

### SD4 — capability false positives go to `knownNoiseSinks`, not the baseline

1.27 rewrote `net/http.ParseCookie` to iterate `strings.SplitSeq`, and capslock's
VTA call graph resolves an app's own `yield` call to that new `func(string) bool`
by type — attributing `CAPABILITY_NETWORK` to an app that performs no network
I/O. `baseline.go`'s own doc settles where this belongs: an accepted finding no
app could honestly act on "is a defect in the table, not debt in the app". The
sink joins `knownNoiseSinks` beside `net/http.containsDotDot$1`, which is the
same artifact found four months earlier in the same app.

This will recur. As the standard library adopts range-over-func inside
capability-branded packages, each new yield closure becomes a candidate callee
for every iterator an app writes. Entries are added one at a time with the
sink's body read — never a package-wide bypass.

## Alternatives

- **Stay on 1.26 until staticcheck works.** Rejected: there is no release to
  wait for — `v0.8.0-rc.1` panics on its own bug under 1.26 as well, so the
  block is not a function of the bump.
- **Bump the toolchain, keep `go 1.26.0`.** Rejected: 310 `stdversion` findings
  across 31 files, and 1.27's `go test` runs that check by default.
- **Drop the tag from `RequiredTags` without retiring it.** Rejected: a consumer
  carrying a recognised-but-meaningless tag is precisely the drift `gov
  buildtags` exists to report (SD1).
- **Retire `boxer_enable_profiling` too, for a genuinely tagless build.**
  Rejected: it gates a `net/http/pprof` import side effect (SD2).
- **Pin staticcheck forward to `v0.8.0-rc.1`.** Rejected: it aborts too, on both
  toolchains.
- **Accept the capslock finding in the baseline.** Rejected: it is an analysis
  artifact, not debt an app could act on (SD4).
- **Make `go fix -diff` a `gov gate` step.** Rejected: one fixer output is
  deliberately declined, so the gate could never be green — and a fixer that
  rewrote two independent variables to one name is not one to run unattended.
- **Adopt generic methods broadly.** Rejected: in `leeway/dml` the type
  parameter *is* the receiver, so nothing converts; `recordstore`'s generated
  cache constructor would convert but the gain is cosmetic against call-site
  churn.

## Consequences

### Positive

- A consumer needs **no build tags**, which unblocks `go tool` delivery of
  boxer's CLI — measured on a consumer-shaped module.
- The `//go:build` gate on `encoding/json/v2` stops being something every
  consuming repository must know about.
- `marshallreflect`'s builder chain closes; ADR-0023 can be designed without
  working around a language limit that no longer exists.

### Negative

- **staticcheck analyses nothing** until upstream ships a working release. This
  is the real cost of the bump, and it is not mitigated, only made visible.
- Every consuming repository must reach Go 1.27 before it can take a new pin.
- One more capability false positive is tolerated in `knownNoiseSinks`, and the
  mechanism predicts more.

### Neutral

- The `,inline` → `,embed` rename is the kind of silent wire-shape change only a
  test that pins a guarantee will catch. Nothing structural follows; it is worth
  recording that `go build` and `go vet` were both clean on it.
- `go mod tidy` churn was negligible — two insertions, five deletions.

## Migration

- **Breaks.** For a consumer: any build on a toolchain older than 1.27, hard,
  with `go.mod requires go >= 1.27.0`. Within this repository: `jsontext.Token`
  accessors, and the `,inline` struct-tag spelling — both already repaired.
- **Path.** (1) The developer or CI host provides Go 1.27; where
  `GOTOOLCHAIN=local` is set, that means installing it rather than letting the
  `go` command fetch it. (2) A workspace file spanning several modules raises
  its own `go` line, which is separate from any module's. (3) A consumer raises
  its module's `go` line, then bumps its boxer pin, then drops
  `goexperiment.jsonv2` from its copied tags file — in that order; dropping it
  earlier breaks its build, and keeping it afterwards is inert until the pin
  brings the retired-set finding. (4) The next airgap bundle is packed on a host
  whose **default** `go` is 1.27: `airgap_ship_goroot` copies `$(go env GOROOT)`
  verbatim, so a `GOTOOLCHAIN` override does not help.
- **Regeneration.** None. No generator input changed, no generated file was
  touched by the `go fix` sweep, and no FFI boundary moves.
- **Old shape.** `goexperiment.jsonv2` is removed outright from `./tags` and
  recorded in `RetiredTags`, which is append-only. The `toolchain` line is gone
  and does not come back.

## Verification plan

| Lane | What would fail | Gap |
| --- | --- | --- |
| `gov gate`'s `buildtags` step | `TestRequiredAndOptionalMatchTagsFile` fails if `./tags` and `RequiredTags` disagree — observed during the trial run, which is the check working | It compares boxer against its own contract; a consumer is only checked when it runs the gate |
| default `go test` (`-race`, `-short`) | the `,embed` guarantee, via `TestEncodeRequestExtraCollisionFails`, which is the only thing that caught the rename | Nothing pins the *other* json/v2 tag options against a future rename |
| `go vet ./...` | test files that stop compiling — `go build ./...` does not compile them, which is how two broken `go fix` rewrites reached a commit | — |
| capslock (`TestAnalyse_MatchesBaseline`) | a real capability appearing, and equally a `knownNoiseSinks` entry that stops reproducing | VTA is a lower bound; the gate cannot distinguish a false positive from a real edge without reading the path |
| a consumer-shaped `go tool` probe | the delivery claim in §Consequences | Run by hand at M2; not a standing lane |
| `lint.sh` staticcheck step | nothing — it is parked, and says so | **This is the gap.** No static analysis of that class runs until upstream is fixed |
