# ADR-0330: A shared audit recorder below the runtime — one sealed writer over a narrow store binding, and the trail built on it

## Context

[ADR-0327](./0327-evidence-as-a-record-store-profile-chain-vault-marks-seals-and-anchors-any-store-opts-into.md)
§SD8 moved `AuditEvent`, its bounds, the recorder's own domain and
`ForwarderI` to
[`evidence/audit`](../../public/storage/recordstore/evidence/audit/doc.go),
so that a process linking no `keelson/runtime` package can record audit
events: "it builds a recorder over the audit package, its own executor and a
forwarder; its rows say `originBy = self`." The package holds the row and the
seam, not the recorder. The one recorder is the trail's
([`trail.Recorder`](../../public/keelson/runtime/trail/recorder.go)), which
links `keelson/runtime/app`, writes `boxer.facts` through a store whose
generated scaffolding is the runtime's, and stays where it is.

What a recorder of audit events does is not small, and most of it is a
contract rather than plumbing ([ADR-0296](./0296-audit-events-as-a-trail-component.md)
§SD2–§SD6, ADR-0327 §SD5): the identity read off the call identity on the
context ([ADR-0295](./0295-recordstore-call-identity-observed-executors-and-write-observers.md))
and `originBy`; a row outside the bounds replaced by an `audit-invalid` row;
a buffer that never blocks a writer, a bounded backlog, and loss written
back as an `audit-gap` row; a seal per durable flush chained to the run's
last durable seal, anchored by scope; reads by subject and by principal; a
forwarder fed by a prompt path and a backstop window; write-ahead; and what
`Close` loses. A downstream service that links no runtime package asked who
builds this (a question of 2026-10-12, its Q2 and Q6). Two recorders exist
downstream because boxer shipped none (observed 2026-10-13), each a copy of
the trail's loop over a store of its own. The copies already differ from the
trail and from each other in what an invalid row keeps, whether the gap row
lands in the flush that found the gap, which order reads return, and whether
a batch stored twice after a lost acknowledgement verifies; the trail's own
`VerifySeals` reports such a batch as a fork (`evidence.OrderSeals` sees two
seals with one predecessor). Rows that a regulator reads as one vocabulary
are being written by three hands.

The tables differ, and that is the constraint on any shared recorder. Each
consumer's store is generated by [`recordstore/gen`](../../public/storage/recordstore/gen/gen.go)
with its own table, its own envelope (a natural key on a facts-shaped
table, a stream column on a table of its own), its own membership ids, its
own read-access scaffolding, and a seal component and `SealOf` emitted into
its own package. Go type parameters do not reach a generated entity's
fields or its envelope, so no generic function binds the generated store
directly.

## Design space (QOC)

**Question.** Who writes audit events below the runtime, so that gap,
invalid and seal rows mean the same on every table?

**Options.**

- **O1 — Each consumer writes its own.** ADR-0327 §SD8 read literally.
- **O2 — A shared recorder over a narrow binding.** A package beside
  `evidence/audit` owns the buffer, the seals, the loss accounting,
  write-ahead, the reads and forwarding, over a small interface a
  generated store meets through a thin adapter; the trail is rebuilt on it.
- **O3 — The trail's recorder made runtime-free and reused.** Split the
  trail so its recorder and store link no runtime package; consumers write
  through the trail's store.
- **O4 — The generator emits the recorder.** A profile switch emits the
  flush loop, seals, reads and forwarding into every store's package.

**Criteria.**

- **C1 — Identical rows.** A gap, an invalid row and a seal stream mean the
  same whichever process wrote them.
- **C2 — Links no runtime.** The recorder and what it imports pass a
  dependency check against `keelson/runtime` and the GUI.
- **C3 — Any generated table.** Envelope, vocabulary and scaffolding are the
  consumer's.
- **C4 — Cost to the trail.** Its verbs, its write-ahead for model calls
  (ADR-0277 §SD3), its tests.
- **C5 — A fix lands once.**

**Assessment.** `++` strong positive, `+` positive, `−` negative, `−−` strong negative.

|    | O1 | O2 | O3 | O4 |
|----|----|----|----|----|
| C1 | −− | ++ | ++ | +  |
| C2 | ++ | ++ | −  | ++ |
| C3 | ++ | +  | −− | +  |
| C4 | ++ | −  | −− | −  |
| C5 | −− | ++ | ++ | −  |

O1 is the drift the Context records. O3 fails C3: the trail's store is
`boxer.facts` with the trail's kinds, the runtime vocabulary's ids and the
runtime's shared read-access scaffolding, and a consumer that wants its own
table — the case ADR-0327 §SD8 was written for — gains nothing from a
runtime-free trail recorder it cannot point elsewhere. O4 gives identical
rows only as long as every consumer regenerates; a fix to the loop is a
regeneration of every store in every repository, generated code is the
hardest to evolve, and the trail's hand-written verbs would still have to
compose with the emitted loop. O2 is taken. Its cost to the trail (C4) is
paid in a milestone of its own (SD8).

## Decision

We will ship one recorder of audit events below the runtime, package
`storage/recordstore/evidence/audit/auditrec`, generic over a narrow
binding that a generated store under `Evidence{Seals: true}` meets through a
thin adapter. The rows it writes about itself and the identity rule are
functions of `evidence/audit`, so they are identical whether `auditrec` or
the trail writes them. The origin becomes a component of the audit package,
so every binding selects a run's rows the same way. The trail's buffer,
seals and audit-event path move onto the shared writer in a later milestone
of this decision, keeping its verbs.

### SD1 — Placement and the fence

`auditrec` is a child of `evidence/audit`, not part of it, and not part of
`evidence`:

- **Not in `audit`.** `audit` is the value package a carrier adapter links
  (ADR-0327 §SD8) and compiles to every WASM target; a recorder brings a
  logger, goroutines, an executor and the anchor contract. A forwarder
  should not link them.
- **Not in `evidence`.** `evidence` holds laws — functions over rows — and
  a recorder with a flush loop is not a law.
- **Not under `keelson/runtime`.** That is the fence the downstream process
  keeps by its own architecture decision.

Its imports are `recordstore`, `evidence`, `evidence/anchor`,
`evidence/audit`, `identity/callident`, the ClickHouse literal marshalling,
`eh`, `option`, zerolog and xxh3; none of them links a `keelson`, `imzero2`
or `egui` package (`go list -deps`, 2026-10-13). A test in the package keeps
that true (Verification plan).

### SD2 — Rows identical by construction

Four functions move into `evidence/audit`, and every writer — `auditrec`,
the trail, a downstream copy until it retires — builds its rows with them:

- **`Stamp(ctx, row, def)`** applies ADR-0296 §SD2's identity rule: the
  principal and the purpose from the call identity's claims, replacing what
  the row carried; no principal forces `PrincipalBy = none` and drops
  `PrincipalVia`; `OriginBy` from the context's attestation, else `def`.
  `PrincipalBy` and `PrincipalVia` beside a principal stay the emitter's
  (ADR-0296 §SD1).
- **`Invalid(row, err, def)`** is the `audit-invalid` row: the recorder's
  domain, the attempted domain and action and the reason as bounded
  attributes, keeping the subject, the node, and a principal with its
  `PrincipalBy` and `PrincipalVia` where they pass the bounds; `OriginBy`
  the row's when it is one, else `def`.
- **`Gap(rows, first, last, originBy, node)`** is the `audit-gap` row: the
  count and the window of the dropped rows' timestamps as attributes, under
  the recorder's `originBy` and node.
- **`OriginOf(ctx, run, def)`** is the origin a row records: the **run is
  the recorder's**, always — it names the seal stream the row belongs to —
  and the context's call identity, when its origin names an app or an
  instance, supplies both; otherwise `def`'s. A call identity that names
  another run does not move a row out of the stream that seals it. This
  changes the trail's `Event`, which took the call identity's run as well.

### SD3 — The origin is a component of the audit package

`audit.Origin` becomes the leeway component the trail's `Origin` is — the
kind `origin`, the row id, and `Run`, `App`, `Instance` on the memberships
the trail spells them with — and `trail.Origin` becomes an alias, as
`trail.AuditEvent` is. The forwarder's `audit.Event` keeps carrying it as a
plain value. A store below the runtime binds it beside `AuditEvent`, so:

- a run's rows and seals are selected the same way on every table — a
  `has()` over the symbol section's values, the exact match on
  `Origin.Run` after decoding — which is what the trail's `VerifySeals`
  does;
- an event read back, by a read or the backstop, carries the origin it was
  forwarded with, so two deliveries of one event agree.

The component's tags do not change, so a trail row's canonical item, and
with it every seal digest, does not move: regenerating the trail store
through the alias wrote byte-identical files (2026-10-13), and
`TestTrailDigestsArePinned` holds the row and seal digests of fixed rows
taken before the move. A forwarded `audit.Event`'s origin carries the row
id in `Origin.Id`, as the component does.

### SD4 — The binding

The recorder reaches a store through two interfaces. Their shape is the
decision; the adapter that meets them is ~110 lines over the generated
builders, written by the consumer in the store's package.

```go
// BatchI is one batch of rows: a generated store opened for writing.
// The recorder uses one from one goroutine at a time.
type BatchI interface {
	// Event buffers one row of o and e, begun with BeginCtx under ctx,
	// and returns its canonical item; on error nothing is buffered.
	Event(ctx context.Context, id uint64, at time.Time, key string, o audit.Origin, e audit.AuditEvent) (item []byte, err error)
	// Seal buffers the batch's seal row, built by the store's generated
	// SealOf from s, and returns the seal's digest.
	Seal(id uint64, at time.Time, key string, o audit.Origin, s SealSpec) (digest string, err error)
	Buffered() int
	Flush(ctx context.Context) error
	Close()
}

// StoreI is a store generated with CanonWire and Evidence{Seals: true}
// that binds audit.Origin and audit.AuditEvent.
type StoreI[B BatchI] interface {
	NewBatch(o recordstore.WriteObserverI[uint64, time.Time]) B
	// Columns are the quoted physical names reads narrow on: the order
	// column and the value columns of the symbol, stringArray and
	// u64Array sections.
	Columns() Columns
	ScanEvents(ctx context.Context, opts recordstore.ScanOpts) iter.Seq2[audit.Event, error]
	// ScanRows reads rows with their origin: a seal as the seal law reads
	// it, any other row with its canonical item.
	ScanRows(ctx context.Context, opts recordstore.ScanOpts) iter.Seq2[Row, error]
	Close()
}
```

The key is the recorder's; the adapter writes it where its envelope keeps
one (a natural-key column) and may ignore it. The adapter computes the
canonical item from the builder's entity before it commits, so a row whose
item cannot be computed is not buffered; the recorder counts it dropped and
fails the call, where the trail writes such a row and leaves it for the
seal law to report as unnamed. `ColumnsFromDDL` reads the value columns
out of the store's generated DDL, so an adapter does not spell them. A store generated with
`WrittenBy` carries the committing identity on every row for nothing, since
the adapter begins rows under the event's context. Where the read table
differs from the write table is the adapter's configuration of the store
(ADR-0296 §SD8).

The recorder is generic over the batch type so that a store with kinds of
its own writes them through the same buffer, seals and backlog: a `Write`
verb hands the typed batch to a closure that adds the row and returns its
canonical item. The trail is that store (SD8).

**Seals are required.** A binding without the seal component is refused at
compile time by the interface. An unsealed audit log is the one ADR-0327's
Context describes — rewritten by an administrator with nothing to show — and
a second flush path for a store nobody has asked for would be the drift
this decision removes. Anchoring stays optional (`WithAnchors(st, cell)`).

### SD5 — The writer

`auditrec.New(st, run, scheme, log, opts...)` is safe for concurrent use,
nil-safe like the trail's, and does what ADR-0296 §SD4 and ADR-0327 §SD5
say, once:

- **Buffer.** Rows are built into the current batch under one lock; a
  flush swaps in a fresh batch and inserts outside it. A flush runs on a
  wake-up, on an interval (one second by default, `WithFlushInterval`), on
  `Flush`, and at `Close`, each bounded (`WithFlushTimeout`).
- **Backlog and gap.** A batch the server did not take is held, oldest
  first; past the cap (`WithMaxBacklog`, the trail's 50 000 rows by default)
  the oldest are dropped, counted and remembered. The flush that next lands
  everything held writes the `Gap` row and lands it **in the same flush**,
  so `Flush` returning nil means the gap is on the server too.
- **Seals.** Each batch carries one seal written as its flush begins,
  naming the batch's rows by the digests of their canonical items, chained
  to the run's last durable seal, kept for a retry, dropped with its batch;
  each durable seal is anchored best-effort as the head of the run's seal
  scope. The scheme and the scope function are the consumer's.
- **Events.** `Event(ctx, at, row)` stamps (SD2), fills `Node` from
  `WithNode` when the row has none, validates, writes `Invalid` in place of
  a row outside the bounds, and never fails the caller for a server reason.
- **Close.** `Close` is idempotent: it runs the final flush within its
  bound, drains the forward queue, then counts what the backlog and the
  current batch still hold as dropped and logs it, with no gap row — nothing
  runs afterwards. A verb or a read after `Close` returns `ErrClosed`
  rather than recording or reading nothing silently. The forward queue is
  closed only once no flush can run, so a flush racing `Close` cannot hand
  it a batch.
- **Counts.** Buffered, written, dropped, invalid, seals, forwarded and
  forward-dropped, as the trail's `Counts`.

### SD6 — Write-ahead below the runtime

`EventWriteAhead(ctx, at, row) (durable bool, err error)` is `Event`, then a
flush; durable says every row buffered before the call, the event among
them, is on the server. It is the trail's verb with the policy as an option:
`WithRequired(true)` returns an error wrapping `ErrNotDurable` when the event
did not land (or the recorder has no store), and the caller must not act;
without it the failure is logged and the caller proceeds. The trail maps
`BOXER_TRAIL_REQUIRED` onto the option; a downstream service names its own
setting. `auditrec` reads no environment variable.

- **The row stays.** An event whose write-ahead failed remains buffered and
  lands with a later flush. A write-ahead row records an intent; a caller
  that then refuses records a second event with outcome `failed` or
  `denied`. Removing one row from a batch is not something a generated
  store offers, and a log that loses the intent loses the evidence that the
  refusal was decided.
- **Concurrent write-aheads coalesce.** A flush swaps the whole buffer, so a
  caller waiting for the flush lock usually finds its row already landed by
  the flush ahead of it; the cost is a round trip per flush, not per event.
- **Completeness stays the consumer's** (ADR-0327 §SD10): the recorder gives
  the verb, not the policy of which events must be written ahead.

### SD7 — Reads and forwarding

- **Reads.** `EventsBySubject` and `EventsByPrincipal` take a `Window` —
  bounds, a limit and an order (oldest or newest first) — narrow by the order column
  and a `has()` over the section's value column, match the slot exactly
  after decoding, and return `audit.Event` values. Subject 0 is refused.
  With `WithNode`, a read sees only that node's rows — several writers may
  share one table. A row id read twice (a batch stored twice after a lost
  acknowledgement) is returned once.
- **`VerifySeals(ctx, run)`** is law L34 and, with anchors, L32 over the
  run's rows read through `ScanRows`; seals and rows read twice count once,
  so a retried batch is not a fork.
- **Prompt path.** The events of a batch travel with the batch and are
  handed to the forwarder once that batch has landed, on a goroutine of the
  recorder's behind a bounded queue; a full queue or a refused hand-off is
  counted and left to the backstop. The ids forwarded lately are kept so
  the backstop skips them.
- **Backstop.** `ForwardWindow(ctx, from, to, page)` re-scans a window of
  stored events — node-scoped, each id once — and hands them over; it is a
  lagged re-scan for the reason ADR-0296 §SD6 gives. `CatchUp(ctx, from,
  until, window)` walks a long interval window by window and returns where
  it got to and how many events it handed over. When it runs and where its
  progress is kept are the caller's.

The prompt path no longer goes through a write observer: the recorder knows
which batch landed, and the observer route needed a map of pending entities
under the writer lock and a second materialisation of the observer's
sequence. `WithWriteObserver` still attaches a caller's observer to every
batch.

### SD8 — The trail on the writer

The trail's buffer, backlog, gap, seals, anchoring, `Flush`, `WriteAhead`,
`Close`, `Counts`, its audit-event path and its reads by subject and
principal become calls of `auditrec`'s writer over a trail binding; its
verbs keep their signatures, its other kinds go through `Write`, and
`Admit` and `BOXER_TRAIL_REQUIRED` stay the trail's. This is milestone M3,
after M2 has run against the example store and a binding over a table with
no natural-key column — the two envelope shapes the interface must serve.
The trail's rows are identical to `auditrec`'s from M1, through SD2 and
SD3, so the delay costs no divergence in what a reader sees.

Refactoring the trail in the same change as the new package was rejected:
the trail's flush carries ADR-0277 §SD3's write-ahead for model calls and
the rows of every verb, and an interface fixed against the trail alone would be fitted
to one envelope. Leaving the trail on its own loop indefinitely was
rejected because its fork on a stored-twice batch, fixed downstream and not
in the trail, is the drift this decision exists to stop.

### SD9 — Descoped

- **The generator emits the binding.** The adapter is mechanical once a
  store binds the origin, the audit event and the seal; what the generator
  cannot see is which envelope column, if any, holds the key. An
  `Evidence` option naming it is the follow-up, taken when a third binding
  is written by hand.
- **The physical value columns as generated constants.** Bindings read them
  from their DDL, as the trail does; a generated per-section map retires
  that.
- **A scheduled backstop with persisted progress**, and the
  insertion-order cursor of ADR-0296 §SD9 (c) that would replace the
  re-scan.
- **Chained (row-by-row) audit stores** and a write-ahead that inserts one
  event alone; the writer is for sealed stores with many writers.
- **Which table** a consumer writes, and whether two writers share
  `boxer.facts`: the binding's, not the recorder's.

### Milestones

- **M1 — The rows shared: `Stamp`, `Invalid`, `Gap` and the run rule in `evidence/audit`; `audit.Origin` as the origin component; the trail on both, its store regenerated (SD2, SD3).** ✓
- **M2 — `auditrec`: the writer, the event verb, write-ahead, reads, `VerifySeals`, forwarding; an in-tree example store generated under `Seals` over a table of its own; a conformance test a binding runs (SD1, SD4–SD7).** ✓
- **M3 — The trail on the writer (SD8).**
- **M4 — The dated Updates on ADR-0277, ADR-0296 and ADR-0327.**

## Alternatives

O1, O3 and O4 are weighed in the QOC. Narrower choices:

- **A binding generic over the generated store itself**, with no adapter.
  Rejected: type parameters cannot reach the entity's option fields or the
  envelope, so accessor functions would be passed in — the adapter again,
  as loose arguments.
- **A stream predicate per binding** (a natural-key prefix, an envelope
  column, a symbol) instead of the origin component. Rejected: three
  bindings, three predicates and three exact-match rules, and an origin
  read back differently from the one forwarded, so two deliveries of one
  event disagree.
- **Seals optional.** Rejected in SD4.
- **The trail's environment variable read by `auditrec`.** Rejected: the
  variable names the trail, and a library below the runtime does not pick a
  deployment's settings.
- **Forwarding through the write observer**, as the trail does. Rejected in
  SD7.

## Consequences

### Positive

- One implementation of loss, invalid rows, seals, write-ahead and
  forwarding; a fix lands once, and the downstream copies retire.
- A process without the runtime gets the trail's guarantees, write-ahead
  included, by writing an adapter over a store it generates.
- A batch stored twice after a lost acknowledgement verifies on the trail.

### Negative

- Every store below the runtime binds one more component, and its rows
  grow by it.
- A consumer writes and maintains an adapter until the generator emits it.
- The trail is touched twice: its store at M1, its recorder at M3.
- The trail's audit events take the run from the recorder; a caller that
  put another run on the call identity sees its row move to the recorder's.

### Neutral

- `auditrec` decides no table, vocabulary, scheme or retention.
- Hosts that never record an audit event still write gap rows, as the
  trail already does.

## Migration — Tier 1

- **Breaks.** `audit.Origin` gains a kind marker and an id; a literal that
  names its fields compiles unchanged, and a comparison of a forwarded
  origin now sees the id. M1 changes the trail's `Event` by the run rule;
  M3 changes `trail.Recorder`'s internals, not its exported verbs.
- **Path.** A downstream recorder regenerates its store with the origin
  component, writes an adapter, and replaces its loop with
  `auditrec.New`. A principal kept under a context key of the consumer's
  own moves to `callident.WithClaims`, with `PrincipalBy` and
  `PrincipalVia` on the row. Rows written before a store bound the origin
  are not selected by run; their stream is verified by the code that wrote
  it, or the table is recreated.
- **Regeneration.** The trail store at M1; the example store at M2.
- **Old shape.** The trail's own loop is removed at M3, with no period of
  two loops.

## Verification plan — Tier 1

| Lane | Goes red when |
| --- | --- |
| `auditrec` unit tests over the example store and a gated executor | an invalid row is written as given; an outage past the cap yields no gap row, the wrong count, or a gap row that lands a flush late; the prompt path forwards an event before its batch landed; `Close` under a closed server reports no loss, or a verb after it records; `EventWriteAhead` with `WithRequired` returns no `ErrNotDurable` when the server refuses |
| `auditrec.TestLinksNoRuntime` | the package's transitive imports reach `keelson`, `thestack`, `imzero2` or `egui` |
| `auditrectest.Conformance`, run by every binding (the example's in `TestExampleConformance`) | an event read back differs from the one forwarded (a field the store's codec does not carry, such as a membership missing from its id snapshot); the identity on the context or the run rule stops reaching the row; a run's rows or seals are not selected; a canonical item read back differs from the one sealed |
| `audit` tests (`TestStamp`, `TestOriginOf`, `TestInvalidAndGapRows`) | the identity rule, the run rule, or the rows a recorder writes about itself change |
| `trail.TestTrailDigestsArePinned`, `trail.TestEventRunIsTheRecorders` and the trail's seal tests | a trail row's canonical item or seal digest moves; the trail's audit event takes another run; a trail verb's behaviour changes under M3 |
| `auditrec` tests on clickhouse-local (default lane, skipped without ClickHouse, as the trail's are) | a batch stored twice reads twice or verifies as a fork; reads or the backstop see another node's row; `CatchUp` stops short of its end |

`testdata/example` is outside `./...`: its generator test and build run
when named by path, and the recorder's tests import it.

Gap: the conformance test checks an adapter against its store, not that a
consumer uses `auditrec` at all; a downstream copy of the loop is not
detectable from this tree. The wasm states of `auditrec` are not asserted.

## Status

Proposed 2026-10-13, with M1 and M2 built: the trail's rows go through
`Stamp`, `OriginOf`, `Invalid` and `Gap`, its store binds the origin
through the alias with its digests unmoved, and `auditrec` passes its unit
tests, the conformance test over the example store on clickhouse-local, and
its dependency test. M3 and M4 are open.
