## The window in brief

This section carries no commit hashes and no links. Everything it claims is
cited in the body below.

Nothing in this window has shipped under a tag. The last tag is still the one
cut early in the previous window.

One through-line dominates: **a model can now operate the apps, under rules
the person sets.** An app publishes the commands and queries it offers. A
dispatcher in the host runs them under a grant the person approves, either
observing, suggesting or acting. The chat becomes the coordinator that drives
them. Around that core, the window built:

- the controls: a ceiling on what the model may do, metering of every model
  call, a built-in moderator that slows and then stops a looping window, and
  an unattended mode;
- the record: one audit trail for model calls, agent actions, grants and
  fetches, and a run journal that is the only source of what the model is sent;
- what the agent can see: window arrangement, captures through one policy
  point, an accessibility-style window tree, and an overlay the agent
  annotates the desktop through.

Beside that arc: ad-hoc datasets published as bundles together with the applet
that reads them; leeway rows rendered for a reader rather than a schema;
real GFS wind in a browser tab that makes no request outside the page; and a
set of SQL parser speed-ups.

What it costs a reader: two commits carry the breaking marker, and about fifteen
more break an interface, a wire format or a stored table without it. The
largest are the retirement of the `E` suffix and the move to urfave/cli v3,
both tree-wide. The audit trail asks a deployment to empty `boxer.facts` once.
Fifty-five ADRs were added; thirteen of them are still proposed.

## Apps that agents can operate (ADR-0269, ADR-0270)

[ADR-0269](../adr/0269-app-operations-a-command-query-contract-agents-drive-under-a-task-grant.md)
(accepted) is the foundation for everything below. An app declares the commands
and queries it offers. A model calls them only under a grant the person approved.

**The contract.** `8ae9a72f` puts an operations catalog on the app manifest.
Argument and result types come from the handler signatures, and `opjson`
derives a JSON Schema and a strict codec for the model from the same types.
`a5586380` adds the dispatcher. It runs at fixed points of each frame, so a
queued command is re-checked against what the person changed in the meantime.
Each decision is recorded as an action row on `boxer.facts` (`e83ad17f`).

**The person stays in charge.** Grants and widenings are approved in host
chrome, outside every app's window (`b8bf64fd`). Each shared window gets a
mode: *observe*, *suggest* or *act* (`855a61fb`). In suggest mode a command
waits as a proposal. A consequential command always waits for a confirmation,
even in act mode (`13cc0be2`). If the person changes something a task read
since its last turn, the task is paused until its next turn (`dbb4c142`).
The dialogs became modals so that an app window cannot cover them (`6caa1921`,
`bb4ca50c`).

**What travels with a call.** Each call carries an on-behalf-of context that
names the task, the chain of actors and the grant's destinations. The HTTP and
model services check it (`51c9c801`). Confined content reaches a remote model
as a data handle, not as text, and untrusted output is marked as such
(`811b8e3b`). A refusal says what would let the call through (`27ac3582`).
An approved grant states its terms back to the model: budget, deadline and
destinations (`5f96d371`).

**Smaller pieces.**

- A task can open windows its grant allows (`14edc1ba`). A launch reports how
  far the window has loaded rather than reporting success early (`d09710fe`).
- A late task is held for more time rather than ended (`df26707e`).
- The person picks a new task's call budget with a slider (`8b6c8e59`).
- Apps' inline help is served to the coordinator's model as `read_help`
  (`4534a0cb`).
- `appops` lets a shared component mount its operations into any app's
  catalog; a state machine was the first (`d9f47197`). An external read now
  receives the full call (`c135b9df`).
- [ADR-0315](../adr/0315-coordinator-tools-as-operation-specs-and-a-contract-for-stateful-tools.md)
  adds rebuild, fork, async and dry-run fields to an operation spec, with a
  footprint check on play (`583a8d65`).

**Play's catalog** ([ADR-0270](../adr/0270-play-operations-catalog-and-agent-limits.md),
accepted) grew from a handful of operations (`072d375c`) to a set for every
pane, after an audit of all 34 panes (`c03178a1`). An agent can:

| | Operations |
|---|---|
| Read the state and results | `get_state`, `describe_result`, `sample_rows` (`072d375c`) |
| Point panes at a split node | `list_panes`, `bind_pane` (`5cd3dd1f`) |
| Learn the schema without running a query | `list_tables`, `describe_table`, `validate_sql`, the rewrite trace (`b5c8ba12`); `get_schema` (`18eaea63`) |
| Find worked queries and functions | `list_snippets`, `read_snippet`, `list_functions` (`7aac1037`) |
| Use ad-hoc datasets | by alias (`2c105f4c`), `bind_dataset` (`4088755f`) |
| Cluster and explain a result | `compute_projection`, `get_projection`, `explain_clusters` (`7fe79928`) |
| Find out why a run failed | `get_diagnostics` (`14e02ed4`) |
| Read a row's canonical forms | `get_canonical` (`58f4b4e9`) |

Two commits make the person and the agent follow the same path. The person's
own gestures (Run, Ctrl+Enter, and so on) now go through the catalog, so a
task notices when the person presses Run (`acb18af7`). Play's own writes take
a dispatch decision and a gate of their own (`98933180`).

**Other catalogs.**

- watchbill's job window. Cancel and retry are consequential (`97616031`).
- regex_explorer (`24f05780`).
- jackstay's plan phase, as `plan_state` (`64c66272`).

## The chat as coordinator

The chat app is the first coordinator. `1e3a6c32` turns a turn into a tool loop
over the host's agent services: request access, list windows, describe an app,
call an operation, open a window. The call tool was renamed `call_operation`
because weak models misused a bare `call`; one trial model sent empty
arguments in nearly every run (`df4070e6`). A scripted model, set with
`BOXER_LLM_SCRIPT`, lets scenes drive the whole loop with no endpoint
(`c9ae111f`, `5c370939`).

The window was rebuilt around that loop:

- **Transcript.** The transcript is now a thread, with no right-aligned
  bubbles (`1ce07c49`, `18c0e297`). The trail of a turn is shown live and kept
  on its tool lines (`3a6c8a64`). A step that is waiting for the person says
  so (`84d7646c`).
- **Message actions.** Retry, regenerate, edit and copy are available, and a
  failure has a Details view (`d7289869`, with `c40becdc` in chatview).
- **Titles and context.** A conversation gets a title from the model, a
  context meter against the model's reported size (`77e36ff7`), and an
  Open-in-mdedit hand-off (`0a60ae08`, `4df41df3`).
- **Asking the person.** The model can ask the person through an inline form
  (`ask_user`, `0f21febd`).
- **Settings and limits.** A Settings panel holds the ceiling (`0b80c16b`) and
  a configurable number of rounds per turn (`ae2fef35`, `59c3561d`).
- **Turn state.** A turn is a declared state machine, so a cancel can no longer
  leave the window stuck in "busy" (`ea54ad5e`).
- **Analytics.** The Analytics panel lists every operation the model could
  reach, with its status and calls, as a list or a graph (`65a19eae`,
  `72d1a45d`; [ADR-0283](../adr/0283-chat-analytics-the-agent-surface-and-what-was-granted-and-used.md)).

**The artefact.** [ADR-0282](../adr/0282-chat-artefact-one-markdown-document-per-conversation.md)
gives a conversation one markdown document that the model edits (`27b801a8`).
Every write names its base revision and returns lint findings from the new
`mdspan` and `mdlint` packages (`9ffb5ae4`). The frontmatter names the session,
and the model cannot change those fields (`3de96f43`).
[ADR-0284](../adr/0284-chat-artefact-screenshots-sealed-under-a-budget.md) adds
screenshots beside the document (`079bf14a`).
[ADR-0287](../adr/0287-chat-pixels-a-setting-for-showing-screenshots-to-the-model.md)
("Pixels") decides whether the model may see those images and who consents. It
has four levels and a switch that keeps pixels to a local model (`a2155ce0`).

## Limits on what the model may do

**A ceiling.** [ADR-0280](../adr/0280-a-ceiling-on-what-a-chats-model-may-do-scored-on-a-ladder.md)
(accepted). The coordinator sends a ceiling with its requests, and the
dispatcher refuses anything above it before the person is even asked
(`687b54c0`). The ceiling is scored on a ladder, which a new `bandscale`
widget draws (`61a8689f`). A local git repository counts as host reach, not
network reach (`5bfc12b7`).

**Metering and moderators.** [ADR-0300](../adr/0300-metered-model-calls-and-rules-a-moderator-writes.md)
(proposed).

- `8ab83bb0` meters every model call. Usage is an open set of named
  quantities, and each call is admitted under budget, rate, concurrency and
  deny rules.
- Cached and reasoning tokens are read from the provider when it reports them;
  missing is not treated as zero (`9b8b1fd9`, `5c177b17`).
- Apps listed in `BOXER_LLM_MODERATORS` may stop tasks, lower ceilings and ask
  the person (`3fbc502e`).

**A built-in moderator.** [ADR-0302](../adr/0302-a-built-in-moderator-loop-signals-and-an-escalation-ladder.md)
(proposed), turned on with `BOXER_MODERATOR` (`8b9ae2c1`). It watches model
calls and action records (`c6a5f47d`, `d1d60a4e`) for loops:

- the same call repeated;
- too many rounds in a turn;
- context growing toward the model's limit;
- a run of errors.

It moves the window up a ladder: note, then slow, then stop.

**Unattended mode.** [ADR-0298](../adr/0298-an-unattended-mode-the-host-decides-within-preset-bounds.md)
(proposed). It is compiled in by a build tag and turned on per run. The host
approves grants and proposals in the person's place, but only within a ceiling
(`211cc372`). More calls, more time and consequential commands still wait for
the person, and every dialog says the mode is on (`177b60a4`).

`BOXER_LLM_TRUSTED_HOSTS` lists model hosts that the sensitivity rules treat
like loopback (`158318ac`).

## One audit trail (ADR-0277, ADR-0295, ADR-0296)

The question this answers: when a session is read back from `boxer.facts`, can
you tell which model call asked for a read, who decided, and which query it
caused?

**One recorder.** [ADR-0277](../adr/0277-one-audit-trail-for-model-calls-and-agent-work.md)
(accepted). `4a96fa7a` makes one recorder the only writer for model calls,
agent actions, grants and HTTP fetches. That is the breaking change listed
above.

- An agent-driven query's `log_comment` stamp names the task and the call, so
  a query run joins its action record by key (`122701d7`, `4944d87b`).
- The trail records what asked for each read and who decided (`1d867861`).
- Play's History marks runs an agent caused (`24346e6a`).
- `trailviews` adds read-only data marts and aggregates over the trail, so it
  can be read in play without decoding lanes (`15b84514`).

**Who a call was made for.** [ADR-0295](../adr/0295-recordstore-call-identity-observed-executors-and-write-observers.md)
(accepted) moves this down into recordstore:

- a call identity on the context, and one `log_comment` format (`8b68d9b4`);
- executors that stamp that identity, plus an observing executor (`e5c86753`);
- generated context-taking verbs, write observers and an actor dimension
  (`bc8da55e`).

**Audit events.** [ADR-0296](../adr/0296-audit-events-as-a-trail-component.md)
(accepted) adds a generic audit-event component (`0cc777e4`, `759a1e3c`).

- Rows that are lost are counted and written back as an audit-gap row
  (`f06afdf9`).
- Events can be read by principal or by subject (`b30adbbc`).
- A forwarder seam takes events at least once, with a lagged backstop
  (`02d63002`).
- Every generated store gains a separate read table (`ed9fd878`).

## The agent harness: a run journal (ADR-0307 – ADR-0320, ADR-0325)

Eleven ADRs were written, built and accepted together (`5988ceba`). They answer
one question: what does a conversation look like if it must survive its
process, be checked for tampering, and never send the model anything that was
not recorded first? The threat model they assume is
[ADR-0307](../adr/0307-threat-model-for-an-interactive-single-person-cell.md):
one person and one host.

- **The journal is the only model input**
  ([ADR-0308](../adr/0308-the-run-journal-is-the-only-source-of-model-input.md)).
  Every act is journaled before it happens. The request is projected from the
  journal, by a Go fold and an equivalent SQL fold
  ([ADR-0309](../adr/0309-context-projection-as-sql-over-the-journal-in-a-local-worker.md)).
  Entries are chained by keyed BLAKE3, and chain heads are anchored
  ([ADR-0314](../adr/0314-tamper-evident-records-chain-digests-and-anchored-heads.md)).
  Compaction is itself a journal entry
  ([ADR-0316](../adr/0316-compaction-as-a-journal-entry-plan-act-apply.md))
  (`03a46b85`).
- **The cell and its exits.** The cell is declared from `BOXER_CELL_*` and
  parsed fail-closed. Exits above the model route's clearance need an approval
  that is verified against the refused call and consumed once
  ([ADR-0312](../adr/0312-exits-sinks-from-the-cell-boundary-approval-tiers-and-exit-budgets.md)).
  The clipboard has one choke point
  ([ADR-0317](../adr/0317-clipboard-and-export-copy-by-reference-and-one-choke-point.md))
  (`11e359d0`), and the CS014 lint enforces it (`2a2f3da0`).
- **What an agent may read.** Relations an agent may read in full are
  generated as DDL
  ([ADR-0313](../adr/0313-agent-schema-generated-relations-an-agent-may-read-in-full.md),
  `a0164a78`).
- **Seams.** The harness gains seams, a decision table and one token meter
  shared by chat, the moderator and metering
  ([ADR-0310](../adr/0310-harness-profile-and-registry-composition-declared-per-seam.md),
  `60188d3d`). The profile holds limits only (`488f94db`).
- **Wiring.** Hostboot starts the journal, anchors, cell and introspection
  (`9723cc8b`). The chat now runs over the journal, with resume, compaction,
  approvals and endorsement (`378d387b`).

**Storage underneath.**

- *Bodies.* Bodies live in a vault, separate from the ledger. The ledger keeps
  only a commitment to each body under a per-entry key, so destroying the body
  and its key erases it while the chain still verifies
  ([ADR-0320](../adr/0320-journal-bodies-in-a-vault-committed-to-the-chain-under-a-per-entry-key.md),
  `dc613cb6`).
- *Ids.* Ids come from tagged streams leased through one row on the server
  ([ADR-0319](../adr/0319-tagged-id-streams-leased-through-one-row-on-the-one-clickhouse-server.md),
  `6f20ac6b`, `6180d671`). A run has one writer process at a time, enforced by
  a lease (`d108fe73`).
- *Record form.* The ledger and vault sit on the facts sections (`18015432`),
  and their records became components
  ([ADR-0325](../adr/0325-the-journals-canonical-form-is-the-canonical-wire-over-its-rows.md),
  `ac46bdb9`). Tool-call arguments are shredded by the new leeway `jsonshred`
  (`81fb9cc0`).
- *recordstore additions.* recordstore gained what the journal needed: a
  Revision role (`00f62e8c`), a generated compare-and-set (`155c0074`),
  ordered and bounded scans (`db6d96e5`), and per-insert settings (`556635f6`).

**Model work belongs to the harness.**
[ADR-0318](../adr/0318-model-inference-is-the-harnesss-apps-expose-operations.md):
mdedit stops calling a model and exposes operations instead (`be7098fd`).

**Closing a window.** A related lifecycle change: a closing window now drains
its app's lifetime scope between Unmount and unload
([ADR-0322](../adr/0322-app-instances-drain-a-lifetime-scope-between-unmount-and-unload.md),
proposed; `db222e6c`, `ce4ba06e`).

## What an agent sees on the desktop

**Arranging windows.** [ADR-0275](../adr/0275-imzero2-window-arrangement-rust-reports-go-decides.md)
and [ADR-0276](../adr/0276-agents-read-and-arrange-windows.md) (accepted).
Rust reports each window's geometry, and Go decides placement: cascade, tile,
columns, rows (`f48c1af7`, which began as a spike; `0bcd2cbc`). The commands
live in a new Window menu (`192b7a5a`). `keelson('windows')` gains geometry
and `keelson('desktop')` is new (`c3d97b5f`). An agent can raise, place and
arrange windows under a grant (`ff6cf8e7`, `1be72565`, `a8e97f33`). A
title-bar double-click maximizes a window (`db1583d8`).

**Captures.** [ADR-0281](../adr/0281-window-captures-through-one-policy-enforcement-point.md)
(accepted). A capture is not a screenshot of the screen. The host replays the
granted windows' share of the frame stream into a separate context
(`26a101b9`, `31f9bbb8`). Every native host can rasterize it (`f78d5a59`).
One capture service decides and enforces policy (`8d265eb9`), records each
capture on the trail (`0704bddb`), and seals the bytes under a key that exists
only in the process (`c013ef01`).

**Window trees.** [ADR-0301](../adr/0301-window-trees-a-capture-format-naming-each-widget-under-the-message-that-drew-it.md)
(accepted) adds a third capture format beside PNG and SVG. It names each
widget under the message that drew it (`12e5b31b`), and every line carries a
reference the model can cite (`b9804f91`).

**inscribe.** [ADR-0297](../adr/0297-inscribe-an-overlay-agents-annotate-the-desktop-through.md)
(proposed) is an overlay the agent annotates the desktop through (`c867ae4b`).
The chat points at a part of a window tree, so the model never sends a
coordinate (`f7cee8f7`). Marks are drawn as pen sketches: circles, highlighter
swipes and corner brackets, chosen by what they point at (`83ae8205`,
`223e6ffb`). Notes avoid covering what they annotate (`a4ae0ecb`, `66551b51`).
The status bar counts the marks and offers Clear (`c1b1c880`).

## Ad-hoc bundles (ADR-0288)

[ADR-0288](../adr/0288-adhoc-bundles-datasets-published-with-the-applet-that-reads-them.md)
(accepted, after two independent reviews). A bundle is an applet document plus
its datasets, published, republished and retracted as one unit (`da4978d4`).
Any window can show one.

- **Publishing.** `publish_result` turns play's main result into a bundle
  (`d7ced655`), and the person can do the same from the top bar (`31c4f726`).
  A grant entry `publish:<prefix>` is standing consent for it (`55d294b8`).
- **Showing.** Play windows open and follow bundles (`b2374e31`). Other apps
  use `sqlapplet.NewBundleView` (`2d754972`), which an agent can drive
  (`39e10852`, `1553956e`).
- **Safety.** Every operation is audited under an attested call context
  (`cc7a77bd`). A read returns the sealed stream as it was sealed
  (`3e3af9c3`). One owner holds each alias, and windows publish under their
  own (`b8c048f1`). A bundle's provenance is recorded as data, not prose
  (`e0632b09`).
- **Convenience.** Datasets are summarised when sealed (`43d9d045`). A task
  can read what it published without a new grant (`bd536af5`). A follower
  says why an alias is waiting (`d07cc471`).

## Leeway rows for readers (ADR-0289)

[ADR-0289](../adr/0289-leeway-rows-for-readers-canonical-forms-a-read-model-and-kinds-in-projection.md)
(accepted) replaces the card JSON with a read model.

- **lwread.** A new package reads a record the way a person reads it:
  attributes named by membership, with values spelled once (`8cc8a156`).
  play's Detail card (`2879f021`) and `get_detail` (`94ea12a3`) both draw from
  it.
- **The lens.** It now bands rows by the caller's clusters, with archetypes as
  data (`fc83e355`). It moves into the Projection panel, and the Experiments
  pane goes (`00efe275`). Two earlier lens refinements in the window fed it
  (`0f855f1f`, `012d8add`).
- **Canonical forms.** `get_canonical` gives an agent a row's canonical
  digests and CBOR items (`58f4b4e9`). Each position is annotated with what it
  holds (`d359e9ea`, `771fcebe`).
- **Handles.** Handles are printed as the physical columns spell them, so the
  copyable spelling and the runnable one agree (`0dccb862`).

Leeway reads through a CTE or a subquery now bind as they do over a table:
`LW_GET*` (`b596105b`), column handles (`b54cde19`) and `LW_COMPONENT`
(`01826f7e`). A failed run names the rewrite it went without (`02b58f31`).

## In a browser tab, for any module (ADR-0278)

[ADR-0278](../adr/0278-tab-mode-for-downstream-apps.md) (accepted) makes tab
mode a library feature for any module, not just this one.

- **The library.** `tabhost` carries the tab binary's body (`84c6e691`).
  `bundle` builds a servable tab from any module (`a62b6e2c`).
- **Checking it.** Both halves carry an IDL fingerprint that the worker checks
  (`cecae8fb`). The browser host's SHA-256 is recorded and published by digest
  on GitHub Pages (`ae01452e`). The gate gains a `tab` step (`ac03b781`).
- **What a tab can do.** HTTP goes out asynchronously, so a slow query no
  longer freezes the tab (`ed56e018`). The tab fetches map tiles itself
  (`8e429cf1`), takes the light theme (`a769d2ba`), and opens an applet
  document from its own origin
  ([ADR-0299](../adr/0299-sql-applets-a-tab-loads-from-its-origin.md),
  `f4797ce0`).

**The Pages demo.** The tab mode now has a public demo, a static page that
makes no request outside its own origin:

- splashscreen and fibscope (`3108bd91`), then the widget gallery
  (`a11a7385`), on a landing page in the IDS style (`dea49f9a`);
- the repository's own complexity map, as a SQL applet over literal rows
  (`c6aa6ae8`, `869f9658`);
- real GFS wind in play (`e501b54c`), from the next section.

## SQL parsing speed (ADR-0304 – ADR-0306)

These are `perf` and `fix` commits, included because together they decide how
fast the SQL parser runs.

- [ADR-0304](../adr/0304-sll-exact-column-qualifiers.md): column qualifiers
  get their own grammar rule (`238d9374`). Before, 29 % of the test suite's
  statements fell back to the slower full LL parse, almost all of them on
  `t.c`.
- [ADR-0305](../adr/0305-ll-islands-in-the-sll-stage.md): the fast SLL stage
  switches to LL inside BETWEEN, CAST and FROM items (`06df1982`).
- [ADR-0306](../adr/0306-memoise-parsing-and-extraction-by-text.md): parsing
  is memoised by input text. One play run had parsed the same few texts
  26–28 times (`e61eeb32`).
- A lock-free `Sync` (`2d176566`).
- Statement text is built in one pass instead of quadratically (`957f6e38`, a
  `fix`). This is what let the complexity map load in a tab.
